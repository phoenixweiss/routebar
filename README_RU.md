# RouteBar

<p align="center"><strong>Выбранные адреса — в обход VPN.</strong></p>

<p align="center"><a href="README.md">English version</a></p>

RouteBar — планируемая утилита для строки меню macOS, которая управляет
небольшими явными группами адресов, направляемых через текущий физический шлюз,
а не через активный VPN-маршрут.

В основе проекта — интерфейс SwiftBar, человекочитаемая YAML-конфигурация и
узко ограниченный привилегированный помощник. RouteBar не является VPN-клиентом
и не заменяет и не перенастраивает системный маршрут по умолчанию.

## Направление разработки

Первая реализация должна:

- объединять домены и необязательные фиксированные IP-адреса в именованные группы;
- разрешать каждый домен в его актуальные IPv4-адреса;
- после каждой смены сети определять физический интерфейс и шлюз заново;
- добавлять только точечные host-route и учитывать только маршруты RouteBar;
- пересобирать маршруты после смены Wi-Fi, шлюза, пробуждения или VPN;
- проверять результат точечными TCP-, TLS- и HTTP-запросами;
- отделять проверки почтового транспорта от правил обхода VPN;
- показывать сеть, шлюз, VPN, группы и состояние через SwiftBar.

## Конфигурация

Предлагаемый путь по умолчанию:

```text
~/.config/routebar/config.yaml
```

Это обычный YAML-файл, принадлежащий пользователю. Он может быть символической
ссылкой: исходник можно хранить в папке внешнего облачного клиента. Например,
[Yonder](https://github.com/phoenixweiss/yonder) может хранить исходник в таком
хранилище и подключать его по ожидаемому локальному пути.

Текущий предполагаемый формат показан в
[примере конфигурации](examples/routebar.yaml). До первого рабочего выпуска
схема не считается стабильной.

## Граница безопасности

RouteBar не должен ради удобства расширять исключение до подсети провайдера или
изменять default route. Перед применением изменений он заново определяет текущий
физический шлюз, повторяет DNS-разрешение и сравнивает желаемое состояние только
с ранее созданными им маршрутами.

Плагин SwiftBar работает без повышенных прав. Отдельный root-owned helper должен
предоставлять только узкие операции планирования, применения, удаления и проверки
маршрутов RouteBar и не принимать произвольные shell-команды.

## Состояние проекта

Сейчас создана публичная основа проекта; устанавливаемой сборки пока нет.
Сначала будут определены архитектура, строгая проверка конфигурации,
привилегированные границы и read-only план маршрутов, и только затем —
автоматическое изменение маршрутов.

## Разработка

Канонический язык проекта — английский. Пользовательская документация на русском
будет поддерживаться одновременно с ней. Зависимости и release-инструменты будут
добавляться только по мере реальной необходимости.
